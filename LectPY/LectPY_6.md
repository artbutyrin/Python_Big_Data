# Лекція 6. Структура проєктів, пакети, імпорти та бібліотеки

---

## 1. Файлова система великих проєктів

У великих проєктах код **розбивають на логічні частини**: пакети (папки з модулями), модулі (окремі `.py` файли), конфіги та скрипти.

**Типова структура (на прикладі проєкту SAM):**

```
SAM/
├── checkpoint / checkpoints    # збережені стани моделей
├── sam/                        # головний пакет
│   ├── dataset/                # робота з даними
│   ├── models/                 # пакет з моделями
│   │   ├── __init__.py
│   │   ├── sam_classic/
│   │   └── sam_lora/
│   └── utils/                  # допоміжні модулі
│       ├── __init__.py
│       ├── base_model.py
│       ├── download.py
│       ├── lora.py
│       └── metric_analyzer.py
├── .dockerignore
├── docker-compose.yaml
├── Dockerfile
├── .env.example
├── .gitignore
├── index.py, index_samlora.py
├── makefile
├── pyproject.toml
└── requirements.txt
```

**Навіщо така структура:**

| Що | Навіщо |
|----|--------|
| Окрема папка під кожну «частину» логіки | Легше знайти код і підтримувати проєкт |
| Модулі в пакетах | Можна імпортувати за шляхом: `sam.utils.download` |
| Конфіги біля кореня | Один місце для залежностей, збірки, Docker |
| `requirements.txt` | Список бібліотек для встановлення в середовищі |

## 2. `__init__.py` — навіщо і як

**Що це:** файл `__init__.py` у папці перетворює її на **пакет Python** (package). Без нього папка — просто каталог, імпорти з неї можуть не працювати або поводитися непередбачувано.

**Навіщо:**

- Python **вважає пакетом** лише ті директорії, де є `__init__.py`.
- Дозволяє писати, наприклад: `from sam.utils import download` або `from sam.utils.download import some_function`.
- У `__init__.py` можна оголошувати, що саме «експортується» з пакета (списки `__all__`, реекспорт функцій/класів).

**Як використовувати:**

- Порожній `__init__.py` — достатньо, щоб папка стала пакетом.
- Якщо потрібно спростити імпорти, у `__init__.py` можна імпортувати й реекспортувати ключові об’єкти.

**Приклад структури з `__init__.py`:**

```
sam/
├── __init__.py      # sam — пакет
├── models/
│   └── __init__.py  # sam.models — пакет
└── utils/
    └── __init__.py  # sam.utils — пакет
```

Після цього можна писати: `from sam.utils.download import ...`, `from sam.models.sam_lora import ...`.

## 3. Бібліотеки для Python та `requirements.txt`

**Бібліотеки** — це зовнішні пакети (модулі), які встановлюються окремо і дають готовий функціонал (робота з мережею, ML, графіка тощо).

**`requirements.txt`** — текстовий файл у корені проєкту, де **перелічені залежності** (назви пакетів і, за бажанням, версії).

**Навіщо він потрібен:**

- Один раз описуєш залежності — усі можуть встановити їх однією командою.
- Легше відтворити середовище (на комп’ютері, у Docker, на сервері).

**Як користуватися:**

```bash
# Встановити все з файлу
pip install -r requirements.txt
```

**Приклад вмісту `requirements.txt`:**

```
numpy>=1.20.0
torch>=1.10.0
opencv-python
```

У великих проєктах часто також використовують **`pyproject.toml`** (сучасний стандарт) для метаданих проєкту та залежностей.

---

## 4. PyTorch та інші бібліотеки

**PyTorch** — популярна бібліотека для машинного навчання та глибокого навчання (тензори, автоматичне диференціювання, нейронні мережі).

У контексті структури проєкту:

- Такі бібліотеки зазвичай вказують у `requirements.txt` або `pyproject.toml`.
- Код моделей часто лежить у пакетах на кшталт `models/` (наприклад, `sam_classic`, `sam_lora`), а використання PyTorch — всередині цих модулів.

**Інші корисні бібліотеки:**

- **NumPy** — робота з масивами та обчисленнями.
- **Pandas** — таблиці та аналіз даних.
- **requests** — HTTP-запити.
- **Django / Flask** — веб-додатки.

Усі вони встановлюються через `pip` і мають бути перелічені в залежностях проєкту.

## 5. Іменовані імпорти — що це і навіщо

**Іменований імпорт** — коли ти імпортуєш **конкретний об’єкт** (функцію, клас, змінну) з модуля або пакета за його **ім’ям**.

**Приклади:**

```python
# Імпорт модуля
import sam.utils.download

# Іменований імпорт — беремо саме функцію/клас
from sam.utils.download import some_function
from sam.models.sam_lora import SomeClass
```

**Навіщо вони потрібні:**

| Перевага | Пояснення |
|----------|-----------|
| Читабельність | У коді видно саме те, чим користуєшся: `some_function()`, а не `sam.utils.download.some_function()`. |
| Зручність | Коротші виклики, менше повторень довгих шляхів. |
| Явність | Зверху файлу видно, які саме функції/класи з якого модуля використовуються. |
| Структура проєкту | Підходить до великих проєктів з пакетами (`sam.utils`, `sam.models` тощо). |

**Повний шлях модуля** (як у дереві файлів, наприклад `sam/utils/download.py`) відповідає **точковому шляху при імпорті**: `sam.utils.download`. Іменовані імпорти дозволяють витягнути з цього шляху лише потрібні імена.

## 6. Оформлення коду: відступи та порожні рядки

Добре оформлений код полегшує читання і підтримку великих проєктів. Нижче — основні правила (PEP 8).

### Відступи (Indentation)

- **4 пробіли** на один рівень відступу.
- Продовження довгого виразу (наприклад, аргументи функції) можна вирівнювати:
  - по відкриваючій дужці, або
  - з **висячим відступом** (hanging indent): тоді на першому рядку не має бути аргументів, а наступні рядки мають бути чітко відокремлені додатковим відступом.

**Приклади прийнятного оформлення:**

```python
# Вирівнювання по відкриваючій дужці
foo = long_function_name(var_one, var_two,
                         var_three, var_four)

# Висячий відступ — аргументи з нового рядка, +4 пробіли
def long_function_name(
        var_one, var_two, var_three,
        var_four):
    print(var_one)
```

**Погано:** аргументи на першому рядку, а далі — без чіткого продовження; або тіло функції на тому ж рівні відступу, що й аргументи.

### Перенос рядка та бінарні оператори

- Краще **переносити рядок перед бінарним оператором** (стиль Кнута): оператор залишається біля свого операнда і вираз легше читати.

**Гірше (оператор в кінці рядка):**

```python
income = (gross_wages +
          taxable_interest +
          (dividends - qualified_dividends) -
          ira_deduction -
          student_loan_interest)
```

**Краще (перенос перед оператором):**

```python
income = (gross_wages
          + taxable_interest
          + (dividends - qualified_dividends)
          - ira_deduction
          - student_loan_interest)
```

### Порожні рядки (Blank lines)

| Де | Скільки порожніх рядків |
|----|--------------------------|
| Між функціями/класами верхнього рівня | **2** |
| Між методами всередині класу | **1** |
| Між групами логічно пов’язаних функцій | можна додатково 1 (рідко) |
| Всередині функції для логічних блоків | 1, не дуже часто |

Це допомагає візуально відокремити великі блоки коду та покращує сприйняття конспекту та самого проєкту.

## Короткі висновки

- Великі проєкти організують у **пакети** (папки з `__init__.py`) та **модулі** (`.py` файли); біля кореня — конфіги та `requirements.txt`.
- **`__init__.py`** робить папку пакетом і дає змогу імпортувати з неї за шляхом `paket.modul`.
- Залежності зберігають у **`requirements.txt`** (або `pyproject.toml`) і встановлюють через `pip install -r requirements.txt`.
- **Іменовані імпорти** (`from paket.modul import функція`) роблять код коротшим і зрозумілішим у великих проєктах.
- Дотримання **PEP 8** (4 пробіли, порожні рядки, перенос перед оператором) покращує читабельність і сприйняття коду.
